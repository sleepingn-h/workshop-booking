# UX 가이드

고객이 클래스를 발견해 신청하고 결과를 확인하기까지, 운영자가 신청을 처리하기까지의 흐름을 설계하는 규칙이다. 색·글자·간격 같은 시각 값은 [UI_GUIDE.md](UI_GUIDE.md)에 있고, 이 문서는 **각 화면이 무엇을 먼저 보여주고 사용자를 어디로 보내는지**를 정한다.

UI 디자인 7원칙(위계·점진적 공개·일관성·대비·접근성·근접성·정렬)을 이 서비스의 예약 흐름에 맞게 옮겼다.

## 핵심 원칙

이 서비스의 사용자는 회원가입 없이 한 번 들어와 신청하고, 나중에 예약번호로 다시 돌아온다. 계정이 없으므로 **예약번호가 고객과 서비스를 잇는 유일한 끈**이다. 모든 화면은 아래 세 가지를 지킨다.

1. **한 화면, 한 다음 단계.** 화면마다 사용자를 다음 단계로 보내는 주요 동작은 하나다. 그 동작만 가장 눈에 띄게 만들고 나머지는 보조 동작으로 낮춘다.
2. **기대를 먼저 맞춘다.** "신청 = 확정이 아님", "결과는 직접 조회", "취소 기한"은 신청 버튼을 누르기 전에 알린다. 신청 후에 알게 되는 규칙은 신뢰를 깎는다.
3. **막히면 길을 준다.** 신청·조회·취소가 거부되면 이유와 함께 사용자가 지금 할 수 있는 다음 행동(다른 회차 선택, 다시 입력, 공방 문의)을 같은 자리에 보여준다. 막다른 화면을 만들지 않는다.

## 7원칙의 적용

| 원칙 | 이 서비스에서의 적용 |
| --- | --- |
| 위계 | 고객이 판단에 쓰는 정보(다음 회차 날짜, 남은 자리, 비용)를 제목 바로 아래, 스크롤 없이 보이는 곳에 둔다. 설명 본문·준비물은 그 아래로 내린다. |
| 점진적 공개 | 신청 폼은 회차 → 인원 → 예약자 정보 순서로 채운다. 회차를 고르기 전에는 인원·입력 칸이 결정을 방해하지 않게 하고, 예약 상세는 번호 확인 뒤에만 연다. |
| 일관성 | 상태 이름(승인 대기·참여 확정·거절됨·취소됨), 배지 색, 버튼 variant를 고객·운영자 화면에서 똑같이 쓴다. 같은 상태를 화면마다 다른 말로 부르지 않는다. |
| 대비 | 고객 화면의 green 버튼은 신청 하나뿐이다. 되돌릴 수 없는 동작은 빨간 버튼으로 끌어당기지 않고, ghost로 열어 다이얼로그의 ink 버튼으로 확정한다. |
| 접근성 | 상태는 색과 글자를 함께 쓰고, 터치 영역은 44px 이상, 모든 입력·제출·확인을 키보드로 할 수 있다. 오류는 해당 입력 옆에 글자로 표시하고 포커스를 옮긴다. |
| 근접성 | 회차의 날짜·시간·남은 자리는 한 행에 묶는다. 예약번호와 복사 버튼은 붙이고, 예약 취소는 조회·복사 같은 일상 동작에서 떨어뜨린다. |
| 정렬 | 좌측 정렬 한 줄 기준선을 지킨다. 정의 목록(예약 상세)은 라벨 열 폭을 고정해 값이 같은 선에서 시작하게 한다. |

## 고객 흐름

```
클래스 목록 ─▶ 클래스 상세 ─▶ 회차·인원 선택 ─▶ 예약자 입력 ─▶ 신청 완료 ─▶ 예약 조회 ─▶ (기한 내 취소)
   발견          판단             결정              확정            보관           확인
```

단계마다 사용자가 품는 질문, 화면이 먼저 답할 것, 다음 단계로 넘기는 장치를 정한다.

### 1. 클래스 목록 — 발견

- **사용자의 질문**: 어떤 클래스가 있고, 장소·시간·비용이 나에게 맞나?
- **먼저 보여줄 것**: 대표 이미지, 클래스 이름, 장소·소요 시간·비용(항목마다 한 줄). 시간·비용은 카드를 열지 않고도 비교할 수 있어야 한다. 장소가 길면 그 줄에서 말줄임한다. 소개·회차·남은 자리는 상세에서 확인한다.
- **다음 단계로 넘기는 장치**
  - 카드 전체가 상세로 가는 링크다. 이미지·제목 어디를 눌러도 이동한다.
  - 상단 소개 문구에 "회원가입 없이 신청"을 적어 진입 부담을 낮춘다.
- **하지 않는다**: 카드마다 신청 버튼을 따로 두지 않는다(상세의 안내를 읽지 않고 신청하게 된다).

### 2. 클래스 상세 — 판단

- **사용자의 질문**: 어디서, 얼마에, 몇 시간이고, 뭘 가져가나? 신청하면 바로 확정인가?
- **먼저 보여줄 것**: 제목 바로 아래에 소개 본문을 별도 제목 없이 둔다. 그 아래 구분선을 긋고 소요 시간·비용·결제 방법·문의처·장소·준비물을 아이콘이 붙은 정보 항목으로 정리한다. 비용 0원은 "무료"로 쓴다.
- **다음 단계로 넘기는 장치**
  - 데스크톱에서는 신청 카드가 오른쪽에 sticky로 따라오고, 모바일에서는 신청 버튼이 하단 고정 바에 있다. 스크롤 위치와 관계없이 다음 동작이 항상 보인다.
  - 신청 버튼 바로 위 안내 상자에 승인 방식("운영자가 확인 후 승인합니다.", "신청 후에는 승인 대기 상태이며 참여 확정이 아닙니다."), 결과 확인 방법, 상태별 취소 기한("승인 대기는 시작 전까지, 참여 확정은 시작 24시간 전까지")을 문장마다 블릿 목록으로 줄을 나눠 둔다.
- **빈 상태 없음**: 예정 회차가 없는 클래스는 공개할 수 없고, 공개 후 예정 회차가 없어지면 고객 목록·상세에서 숨겨진다(R-59). 그래서 상세의 신청 카드에는 "예약 가능한 회차 없음" 상태를 두지 않는다.

### 3. 회차·인원 선택 — 결정

- **사용자의 질문**: 이 날짜에 우리 일행이 다 들어갈 수 있나?
- **규칙**
  - 회차는 라디오 카드로 보여주고 날짜(굵게)·시간·남은 자리를 한 행에 둔다. 2자리 이하는 magenta로 "N자리 남음", 0이면 "마감"으로 표시하고 선택할 수 없게 한다.
  - 회차를 고르기 전에는 신청 버튼을 누를 수 있어도 되지만, 누르면 회차 목록으로 포커스를 옮기고 "회차를 선택해 주세요."를 보여준다.
  - 인원은 1~4명이다. 선택한 회차의 남은 자리보다 많은 인원을 고르면 그 자리에서 "남은 자리보다 많은 인원은 신청할 수 없습니다."를 보여준다. 제출 후에 알리지 않는다.
  - 선택 상태는 테두리 색과 배경, `aria-checked`로 함께 표현한다.

### 4. 예약자 입력과 신청 — 확정

- **사용자의 질문**: 무엇을 입력해야 하고, 개인정보를 어디에 쓰나?
- **규칙**
  - 입력은 이름과 전화번호 두 칸뿐이다. 칸을 늘리지 않는다.
  - 전화번호는 하이픈·공백이 있어도 받는다. 형식을 강요하는 마스크를 두지 않고, 보조 설명에 "결과 조회 때 뒷자리 4자리를 사용합니다"라고 쓰임새를 알린다.
  - 오류는 blur 또는 제출 시 해당 칸 아래에 표시하고 첫 오류 칸으로 포커스를 옮긴다. 입력한 값은 지우지 않는다.
  - 제출 중에는 버튼을 비활성화하고 "신청 중…"으로 바꾼다. 두 번 눌러 중복 신청되지 않게 한다.
- **신청이 거부되면**: 입력을 유지한 채 아래 [막혔을 때의 안내](#막혔을-때의-안내)대로 다음 행동을 제시한다. 특히 직전에 자리가 찬 경우에는 회차·남은 자리를 다시 불러오고 "남은 자리가 바뀌었습니다. 회차와 인원을 다시 확인해 주세요."를 회차 목록 위에 보여준다.

### 5. 신청 완료 — 보관

계정이 없으므로 이 화면의 목표는 **예약번호를 고객 손에 쥐여주는 것**이다.

- **먼저 보여줄 것**: 체크 아이콘, "예약 신청이 접수되었습니다", 그리고 화면에서 가장 큰 글자로 예약번호와 바로 옆 복사 버튼.
- **진행 단계 표시**: 신청 → 운영자 확인 → 참여 확정 3단계 막대를 두고 현재 위치(운영자 확인 대기)를 표시한다. 사용자가 전체 과정 중 어디에 있는지, 남은 단계가 무엇인지 알 수 있다.
- **신청 내용**: 진행 단계 아래에 상태·클래스·신청자·일시(시작~종료)·장소·인원을 둔다. 신청자는 조회 화면처럼 이름·전화번호 일부를 가린다. 신청한 탭에서만 보이고, 다른 탭·기기에서 연 주소에는 보이지 않는다.
- **다음 단계로 넘기는 장치**
  - 번호 바로 아래 안내 상자에 "예약번호를 보관해 주세요."와 "조회·취소할 때 예약번호가 필요해요."를 블릿 목록으로 줄을 나눠 둔다.
  - 주요 동작은 "예약 조회" 하나다. 이동할 때 예약번호를 미리 채워 고객은 뒷자리 4자리만 입력한다.
  - 복사 성공은 토스트로 짧게 알린다.
- **하지 않는다**: 주소의 예약번호만으로 서버에서 예약 상세를 불러오지 않는다. 주소만으로 남의 예약을 볼 수 없게 하기 위해서다. 화면의 신청 내용은 신청 폼이 같은 탭에 넘긴 값이고, 서버 기준 상태·상세는 조회 화면에서 뒷자리를 확인한 뒤에만 보여준다.
- 주소에 번호가 있으므로 새로고침하거나 북마크해도 예약번호가 나온다. 신청 내용은 신청한 탭에서만 남는다. 번호가 없는 주소로 들어오면 예약 조회로 안내한다.

### 6. 예약 조회 — 확인

- **사용자의 질문**: 승인됐나? 언제까지 취소할 수 있나?
- **입력**: 예약번호와 전화번호 뒷자리 4자리. 뒷자리 칸은 `inputmode="numeric"`, 최대 4자.
- **실패 시**: 어느 값이 틀렸는지 구분하지 않고 "예약번호 또는 전화번호 뒷자리를 다시 확인해 주세요"를 보여준다. 바로 아래에 "예약번호를 분실하셨나요? 공방에 예약자 이름과 전체 전화번호로 문의해 주세요."를 둔다.
- **화면 전환**: 조회에 성공하면 입력 폼을 내리고 결과 화면으로 바꾼다. 브라우저 뒤로 가기는 입력 폼으로 돌아간다. 결과 화면 맨 위에는 "클래스 목록" 링크를 두고, 클래스가 고객에게 보이면 결과 제목 오른쪽에 "클래스 상세 보기" 링크를 둔다. 비공개이거나 예정 회차가 없는 클래스는 상세가 열리지 않으므로 이 링크를 숨긴다. 뒷자리는 주소에 남기지 않으므로 결과 화면을 새로고침하면 예약번호가 채워진 입력 폼에서 뒷자리만 다시 입력한다.
- **성공 시 위계**
  1. 상태 배지와 클래스 이름.
  2. 신청자, 일시(시작~종료), 장소, 인원(예상 비용), 결제 방법, 문의처. 종료 시각은 시작 시각에 소요 시간을 더해 보여준다. 예상 비용은 1인 비용에 인원을 곱해 "2명 (예상 비용 ₩90,000)"처럼 인원 옆 괄호에 쓴다. 신청자는 "이*윤 · 010-****-7890"처럼 이름·전화번호 일부를 가린다. 준비물과 소개는 표시하지 않고 클래스 상세에서 확인한다.
  3. 안내 상자: 직접 취소 기한(포인트 컬러 강조) → 상태의 의미 한 줄(승인 대기면 "승인 대기는 참여 확정이 아닙니다.") → 취소 규칙. 기한이 지났으면 기한 경과 안내 → 상태의 의미. 최종 상태 예약은 상태의 의미만 둔다. 상태의 의미는 취소 규칙과 같은 보조 글씨로 쓴다.
  4. 동작 줄: 예약 취소(최종 상태면 다른 회차 신청하기)와 다시 조회.
- **다시 확인하기**: 승인 결과는 자동으로 알리지 않으므로 "다시 조회" 버튼을 상세 아래 동작 줄 오른쪽 끝에 soft 버튼으로 둔다. 최종 상태 예약에서도 같은 자리에 둔다. 고객이 다른 날 다시 열었을 때도 같은 흐름으로 확인한다.
- **시작이 지났는데 승인 대기**면 "참여 미확정 — 공방에 문의해 주세요"를 상태보다 눈에 띄게 보여준다.

### 7. 예약 취소 — 되돌릴 수 없는 동작

- 취소 트리거는 ghost 버튼으로 상세 아래 동작 줄 왼쪽 끝에 두어, 오른쪽 끝의 다시 조회 버튼과 떨어뜨린다.
- 다이얼로그 제목은 "예약을 취소할까요?", 본문은 "취소한 예약은 되돌릴 수 없습니다. 다시 신청할 때 기존 자리가 보장되지 않습니다." 버튼은 [돌아가기(ghost)] [예약 취소(ink)] 순서다. 기본 포커스는 돌아가기에 둔다.
- 취소 후에는 같은 화면에서 상태가 "취소됨"으로 바뀌고 토스트로 알린다. 다른 회차로 다시 신청하려는 고객을 위해 클래스 상세 링크를 함께 둔다.
- 기한이 지나 직접 취소할 수 없으면 버튼을 숨기지 않고 비활성으로 두며, 바로 위 안내 상자에 이유를 적는다. 문의처는 상세의 문의처 행에서 바로 걸 수 있다. "문의만으로 취소가 완료되지는 않습니다."를 함께 쓴다.

## 운영자 흐름

운영자 화면의 목표는 **승인 대기 건을 빨리 처리해 다른 고객의 자리를 막지 않는 것**이다. 승인 대기도 자리를 차지하기 때문이다.

```
로그인 ─▶ 예약 목록(승인 대기 먼저) ─▶ 승인·거절·취소
       └▶ 클래스 목록 ─▶ 클래스 편집(안내·이미지·회차) ─▶ 공개
```

### 예약 목록

- 로그인 직후 도착하는 화면이다. 제목 아래에 "승인 대기 N건 · 시작 전 회차만 승인할 수 있어요"를 두어 처리할 양을 먼저 알린다.
- 목록 위에 회차 선택과 예약자 검색을, 그 아래에 상태 탭(전체·대기·확정·거절·취소, 탭마다 건수)을 둔다. 탭 건수는 회차·검색 조건을 적용한 결과 기준이다.
- 승인 대기 행에는 [거절][승인], 시작 전 확정 행에는 [예약 취소]가 보인다. 더 처리할 수 없는 행은 비활성 버튼으로 결과를 보여준다(시작한 확정 = "진행 완료", 거절·취소 = "처리 완료"). 시작한 회차의 승인은 비활성 + `title`("시작한 회차는 승인할 수 없어요")로 막는다.
- 승인은 확인 단계 없이 바로 처리하고, 거절·예약 취소는 다이얼로그로 확인한다. 다이얼로그에는 예약자·회차를 다시 보여주고 "N자리가 다시 열려요. 자동 알림이 없으니 고객에게 직접 연락해 주세요."를 둔다.
- 처리 후에는 목록을 다시 불러와 상태가 바뀐 것을 그 자리에서 보여준다. 필터는 유지한다.
- 이름·전화번호 검색은 예약번호 분실 문의 대응용이다. 입력하면 잠시 뒤 자동으로 검색하고, placeholder에 "이름 또는 전화번호"를 쓴다.
- 취소된 회차와 지난 회차의 행은 배경을 낮춰 처리 대상과 구분한다.

### 클래스 준비와 공개

새 클래스는 비공개로 만들어진다. 클래스 목록 머리에 "새 클래스는 비공개로 만들어져요. 회차를 추가한 뒤 공개로 바꾸세요."를 두고, 행마다 공개 스위치·예정 회차 수·승인 대기 건수를 보여준다. 공개 중인데 예정 회차가 없으면 예정 회차 수 옆에 "고객에게 보이지 않아요"를 오류 색으로 붙인다.

새 클래스 화면은 왼쪽에 기본 정보, 오른쪽 보조 영역에 대표 이미지를 둔다. 편집 화면은 왼쪽에 기본 정보·회차, 오른쪽 보조 영역에 대표 이미지·공개 스위치·클래스 삭제를 둔다.

1. 기본 정보: 클래스명, 소개, 장소, 소요 시간, 비용(1인), 결제 방법, 문의처, 준비물을 칸마다 따로 받는다. 소개만 선택이고 나머지는 저장할 때 모두 필수다.
   - 필수 칸은 라벨 옆에 magenta `*`를 붙이고(스크린 리더에는 `aria-required`로 알린다), 카드 머리에 "* 필수 입력"을 둔다.
   - 소요 시간·비용은 숫자만 받고 입력칸 안 오른쪽에 단위("분", "원")를 둔다. 비용 아래에는 고객에게 보일 표기(`₩45,000`, 0원은 "무료")를 미리 보여준다. 천 단위 쉼표는 입력해도 받는다.
   - 저장 시 빈 칸·범위 밖 숫자는 칸마다 오류를 보여주고 첫 오류 칸으로 포커스를 옮긴다.
   - 편집 화면에서 저장에 성공하면 토스트와 함께 클래스 목록으로 돌아가 반영된 내용을 보여준다. 실패하면 화면에 머물고 입력을 유지한다. 새 클래스는 만든 뒤 회차를 이어서 추가하도록 편집 화면으로 간다.
2. 대표 이미지: 편집 화면에서는 버튼으로 파일을 고르면 바로 업로드하고 미리보기를 바꾼다. 새 클래스 화면에서는 고른 파일을 미리보기로만 보여주고, 저장해 클래스가 만들어진 뒤 이어서 올린다. 이미지 업로드만 실패하면 클래스는 그대로 두고 편집 화면에서 다시 올리도록 안내한다. 형식·크기가 맞지 않으면 고르는 즉시 오류로 알린다.
3. 회차: 미래 시각과 1 이상의 정원으로 추가한다. 회차별로 정원 대비 차지된 자리를 미터로, 승인 대기가 있으면 건수를 보여준다. 지난 회차와 취소된 회차에는 동작 버튼을 두지 않는다.
4. 공개 전환: "고객에게 공개" 스위치로 바로 바꾼다. 공개 상태는 제목 옆 배지로 항상 보인다. 예정 회차가 없으면 공개 요청을 보내지 않고 회차 추가로 안내한다(R-59).
   - 클래스 목록: "회차를 먼저 추가해 주세요" 확인 창에 "(클래스명)에 예정 회차가 없어 공개할 수 없어요. 회차를 추가한 뒤 공개로 바꿔 주세요."와 [돌아가기]·[회차 추가하기]를 둔다. [회차 추가하기]는 그 클래스 편집 화면으로 가서 회차 추가의 시작 일시 칸에 포커스한다.
   - 편집 화면: 공개 설정 카드에 "예정 회차가 없어 공개할 수 없어요. 회차를 먼저 추가해 주세요."와 [회차 추가하기]를 보여준다. 버튼은 회차 추가의 시작 일시 칸으로 스크롤·포커스한다. 회차를 추가하면 안내가 사라지고, 스위치로 다시 공개한다.
   - 공개 중인데 예정 회차가 없으면 공개 설정 카드에 "예정 회차가 없어 지금은 고객에게 보이지 않아요. 회차를 추가하면 다시 보여요."를 둔다.

- 예약 이력이 있는 회차는 삭제·시각 변경 대신 "회차 취소"를 제시하고, 확인 다이얼로그에 함께 취소될 활성 예약(예약자·전화번호·인원)과 "자동 알림이 없어요. 위 예약자에게 직접 연락해 주세요."를 보여준다.
- 클래스 삭제가 막히면(회차가 있음) 삭제 버튼을 비활성으로 두고 "회차가 있어 삭제할 수 없어요. 대신 비공개로 전환하세요."를 쓴다.

## 화면 상태

목록·상세·예약 조회·운영자 화면은 네 가지 상태를 구분해 보여준다.

| 상태 | 표시 | 다음 행동 |
| --- | --- | --- |
| 로딩 | 실제 레이아웃 모양의 자리 표시(카드·행 형태). 스피너만 띄우지 않는다. | — |
| 빈 결과 | 왜 비었는지 한 줄 + 할 수 있는 일 | 필터 해제, 문의처, 클래스 추가 등 |
| 실패 | "불러오지 못했습니다" + 서버 사유 | 재시도 버튼 |
| 처리 중 | 누른 버튼만 비활성 + "…중" 문구 | — |

## 막혔을 때의 안내

서버 오류 코드마다 사용자에게 보여줄 다음 행동을 정한다. 오류 문구는 서버가 준 메시지를 쓰되, 다음 행동은 화면이 붙인다.

| 코드 | 상황 | 화면이 제시할 다음 행동 |
| --- | --- | --- |
| `VALIDATION_ERROR` | 입력 형식 오류 | 해당 칸 아래 문구, 첫 오류 칸에 포커스 |
| `INVALID_HEADCOUNT` | 인원 범위 밖 | 인원 선택으로 포커스 |
| `SESSION_FULL` | 직전에 자리가 참 | 회차·남은 자리 다시 불러오기, 입력 유지, 다른 회차·인원 선택 안내 |
| `SESSION_CANCELLED` · `SESSION_STARTED` | 신청 불가 회차 | 회차 목록 갱신, "회차를 다시 선택해 주세요" |
| `DUPLICATE_BOOKING` | 같은 회차에 이미 신청 | 예약 조회로 가는 링크 |
| `BOOKING_NOT_FOUND` | 조회 정보 불일치 | 다시 입력, 예약번호 분실 시 문의 안내 |
| `CANCEL_DEADLINE_PASSED` | 취소 기한 지남 | 문의처 표시, "문의만으로 취소가 완료되지는 않습니다" |
| `INVALID_TRANSITION` | 이미 처리된 예약 | 목록·조회 다시 불러오기 |
| `CAPACITY_BELOW_OCCUPIED` | 정원을 차지된 자리보다 줄임 | 현재 차지된 자리 수를 문구에 포함 |
| `SESSION_HAS_BOOKINGS` | 예약 이력 있는 회차 삭제·시각 변경 | "회차 취소 후 새 회차 만들기" 안내 |
| `CLASS_HAS_SESSIONS` | 회차가 있는 클래스 삭제 | "비공개로 전환" 안내 |
| `NO_UPCOMING_SESSIONS` | 예정 회차가 없는 클래스 공개 | 토스트 대신 회차 추가 안내(확인 창·공개 설정 카드), 회차 목록 다시 불러오기 |
| `UNAUTHORIZED` | 운영자 세션 만료 | 로그인 화면으로 이동 |
| `INTERNAL_ERROR` | 예상하지 못한 오류 | 재시도 버튼, 입력 유지 |

## 문구 규칙

- 존댓말 평서문을 쓴다("~합니다", "~해 주세요"). 운영자 화면의 짧은 안내만 "~해요"를 허용한다.
- 버튼은 동작을 동사로 쓴다: "예약 신청하기", "조회하기", "예약 취소". "확인"·"OK" 같은 모호한 라벨을 쓰지 않는다.
- 상태 이름은 승인 대기 · 참여 확정 · 거절됨 · 취소됨 네 가지만 쓴다. "대기중", "완료" 같은 변형을 만들지 않는다. 예외로 운영자 예약 목록의 상태 탭은 짧은 라벨(대기·확정·거절·취소)을 쓴다.
- 시각은 항상 한국 시각으로 쓴다. 시간대를 따로 알리는 문구는 두지 않는다.
- 오류 문구는 사용자를 탓하지 않고 다음 행동으로 끝낸다("회차를 다시 선택해 주세요").
- 결과를 자동으로 알리지 않는다는 사실을 숨기지 않는다. 신청 전·완료·조회 화면에서 "결과는 예약 조회에서 직접 확인"을 일관되게 말한다.
