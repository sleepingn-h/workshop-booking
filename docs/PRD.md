# PRD: 공방 클래스 예약 서비스

## 목표
고객이 공방 클래스의 일정과 남은 자리를 확인해 회원가입 없이 예약을 신청하고, 운영자가 신청을 확인해 참여를 확정한다. 신청 완료는 참여 확정이 아니며, 운영자 승인 후 확정된다.

MVP의 완료 목표는 배포된 서비스에서 **예약 신청 → 운영자 승인 → 고객 조회 → 고객 취소 → 자리 복구**를 직접 시연하는 것이다.

## 사용자
- **고객**: 회원가입 없이 클래스를 둘러보고 회차·인원을 골라 예약을 신청한다. 예약번호와 전화번호 뒷자리 4자리로 결과를 조회하고 기한 내에 취소한다.
- **운영자**: 비밀번호로 로그인해 예약 목록을 확인하고 승인·거절·취소한다. 클래스·회차와 이미지를 관리하고, 예약번호 분실 등 고객 문의에 대응한다.

## 핵심 기능
1. **클래스 탐색**: 공개 클래스 목록·상세(장소·소요 시간·비용·준비물·문의처), 회차별 시작 시각·정원·남은 자리. 신청 폼을 포함한 공개 클래스 상세는 검색 엔진 노출과 링크 공유 미리보기 지원. 신청 완료·예약 조회·운영자 페이지는 검색 노출 제외
2. **예약 신청**: 회차와 1~4명 인원 선택, 이름·전화번호 입력. 정원 초과·중복·시작한 회차 신청을 막고, 동시 신청에도 정원을 넘지 않는다
3. **예약 조회·취소**: 예약번호 + 전화번호 뒷자리 4자리로 상태 확인. 승인 대기는 시작 전까지, 확정은 시작 24시간 전까지 직접 취소하며 취소하면 자리가 복구된다
4. **운영자 예약 처리**: 로그인·로그아웃, 회차·상태별 예약 목록(취소된 회차 구분 표시), 예약자 이름·전화번호 검색, 승인(시작 전까지)·거절·취소
5. **클래스·회차 관리**: 클래스 생성(비공개로 시작)·수정·삭제·공개 전환(예정 회차가 있어야 공개하고, 없으면 회차 추가로 안내. 공개 후 예정 회차가 없어지면 고객 화면에서 자동으로 숨김), 장소·소요 시간·비용·결제 방법·준비물·문의처를 칸별 필수 입력으로 관리, 대표 이미지 업로드(새 클래스는 생성과 함께), 회차 생성·수정·삭제·취소. 예약 이력이 있는 회차는 삭제·시각 변경 대신 취소하며, 취소하면 활성 예약이 함께 취소된다
6. **반응형**: 고객·운영자 화면 모두 모바일~데스크톱에서 모든 기능 사용 가능

시간 제한의 판정 기준과 처리 구조는 ARCHITECTURE.md, 주요 결정의 이유는 ADR.md에 정리한다. 테스트 이름에 쓰는 규칙 ID(`R-xx`)와 정책 요약은 README에 둔다.

## MVP 제외 사항
- 고객 회원가입·로그인
- 서비스 내 결제·환불
- 자동 문자·이메일 알림
- 승인 대기 예약의 자동 만료
- 고객의 예약 내용 직접 수정 (취소 후 재신청)
